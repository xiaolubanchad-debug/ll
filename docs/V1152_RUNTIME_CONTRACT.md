# 1.15.2 运行环境与启动检查

2026 年 10 月 31 日，执行端 Agent 0.13.2。继承 1.15.1 的每台 EC2 同时一个模拟器，以及 30 款档案和设备内多个不同 APP 的规则。

SDK 发布只能选择官方稳定通道（channel-0）且 revision 不含 preview 的依赖。旧元数据省略 channelRef 时按稳定通道处理。不得因预览版排列在 XML 前面而优先选中；稳定通道不存在则拒绝发布。签名发布继续固定 URL、版本和摘要，已有发布不重写。正例：预览版在前、稳定版在后，选中稳定版；反例：仅有 beta/canary 时自动降级接受预览依赖。

启动检查识别进程的正常退出、信号退出和创建失败。只清理本次创建的进程，先请求结束，有界等待后升级为强制结束；仍未确认结束时拒绝删除工作目录和声明清理成功。已经退出的进程不等待过去的退出事件。任务的 Android 启动等待同样识别信号退出，不空等完整启动超时。

检查模拟器必须从该次检查的独立工作目录启动，不能继承 SSH 或部署进程所在目录。该目录由执行账户创建并可访问。正例：SSH 的起始目录不可被执行账户访问，检查仍从其自己的目录启动；反例：QEMU 在不可访问的继承目录读取相对配置路径，因权限拒绝提前退出。

30 款档案使用 r3 私有目录和版本 3 的内部镜像清单。system.img 与 vendor.img 均处理已核对的 ext4/GPT 布局，GPT 的 ODM 分区包含在型号、品牌、制造商的替换范围；不改变系统版本、ABI 或 OEM 身份声明。两个镜像分别记录并校验 SHA256，启动回执也绑定两个摘要。旧 r2 目录不能作为 r3 的完成标记或启动证明。正例：Android 10 的 ODM 属性与实际 ro.product.model 一致；反例：只修改 system/vendor 的命名空间属性，而 APP 读取的总型号仍为 SDK 默认值。

GPT 中直接存放 ext4 的旧布局与 super 逻辑分区布局分别核对范围。Android 10 的 vendor 分区内还包含 odm/etc/build.prop，必须一并处理。只修改固定属性文件中的型号、品牌、制造商，不把其他文件或整个分区当作文本替换；未知布局仍拒绝。

自动化测试、正式发布、真实 Android 启动和自有 APK 端到端任务分别记录结果。稳定版选择正确不代表所有系统版本已经启动验证；全部档案仍须通过实际型号、系统 API、ABI 和摘要检查才可启用。
