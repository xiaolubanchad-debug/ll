# 1.15.1 单模拟器执行

2026 年 10 月 31 日用户最新要求：每台 EC2 同时只运行一个模拟器，以降低 CPU 压力。此契约覆盖 1.13 和 1.15 的双路执行与验收要求；30 款型号、十个独立 APK、设备内随机安装不重复 APP 的规则继续生效。执行端版本为 Agent 0.13.1。

中台新生成的执行计划固定 openPolicy.concurrency=1，节点数据库锁继续使部署、下载和不同任务互斥。配置向导只显示一台模拟器，导入或编辑旧双路配置时保存为 1。历史不可变配置、事件和结果继续支持读取原值 2，不改写既有统计；高级接口携带的旧值 2 不提高实际执行并发。

Agent 对新旧执行快照都最多启动一个设备会话；旧单 APP 循环同样限制为一个执行中的 APP。一个会话全部 APP 完成、停止或失败后，必须确认整机清理完成才可创建下一会话。APP 清理失败立即停止新增，未知结果仍不得自动重试。

正例：十个包，每台安装 3～5 个，合计目标 10 次，启动第一台新模拟器并串行运行抽中的 APP，关闭整机后再启动下一台；模拟器峰值为 1。反例：UI、旧值 2 或多个任务请求导致两台模拟器同时运行，均不符合本契约。历史双路回执仅用于兼容读取与状态校验，不代表允许新派发双路执行。

验证包括旧值兼容、计划固定为 1、设备会话和旧循环的实际并发峰值、随机不重复、额度、停止与清理、日志及耗时。原双并发真实验收取消，改为单模拟器连续会话验收；未执行的范围不声称通过。

升级时可以复用同一 SDK 和目录中已经逐款启动验证的只读基础镜像。复用前必须重新核对 root 所有且不可由执行账户写入的启动回执、全部 33 个档案的型号/API/摘要/ABI，以及每个 system.img 的实际摘要；不符合则重新逐款启动，不静默接受。每次发布仍做基础 Android 冷启动检查。此缓存仅是基础镜像，任务仍创建新的模拟器和用户数据分区。

镜像兼容修正使用 r2 私有目录，不能把旧目录当作已经验证的新档案。替换属性较长时，只压缩生成器的无功能注释标题并维持原文件长度；版权、许可证、其他属性、真实系统版本和 ABI 保留。无足够空间则拒绝，不能截断属性。GPT 逻辑分区通过 e2fsprogs 的只读 offset 视图读取和定位，不再整份导出临时分区；写入位置仍限定在已核对的分区范围。复制私有镜像时保留零区稀疏布局，逐个摘要验证，SDK 字节不变。
