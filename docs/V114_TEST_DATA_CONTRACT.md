# 1.14 测试档案、自有 APK 与测试数据

版本 1.14.1，Agent 0.12.1，自有 APK 1.0.1。用户明确要求同时实现 1）可验证型号的测试镜像档案；2）每轮独立数据与 Android ID；3）自有 APK 的实际请求 UA；4）中台统一分配及生效检查，并增加自有测试 APK 和“测试数据”菜单。

主业务仍为 Node.js 24 / TypeScript strict。新增的原生 Android 客户端只使用 Java 和 Android SDK；其源码及 Node 构建工具入 Git，签名私钥、APK、系统镜像、实际账户和执行回执不入 Git。APK 源文件和签名不因每轮档案变化而修改。自有 APK 的 UA 可通过预设的测试入口配置；第三方 APK 的自定义 UA 继续标记未验证。

## 档案和执行

测试镜像由节点上的固定构建程序从已校验、已接受许可证的 SDK 镜像生成，仅保存于私有节点目录。保留原 SDK 镜像，记录来源及每个产物的 SHA-256。型号档案使用明确的测试品牌/型号；不声称模拟器变成真实品牌硬件。先验证三个不同型号，再扩充可用档案。运行只接受已构建并验证的档案白名单，不接受任意镜像路径、属性名或 Shell。中台配置启用随机档案后，同批次无放回分配；两路不能占用同一档案，池不足明确拒绝，不循环复用或伪造生效。

首批固定为 `qa-model-01` 至 `qa-model-03`，实际型号为 `QA-Mobile-0001` 至 `QA-Mobile-0003`，仅支持 API 35 x86_64 / en-US。节点心跳 `versions.identityModels` 表示已实际启动校验的数量。同批次尝试上限不得超过该数量；任务下发时冻结 `openPolicy.variantIds`。默认 SDK 不修改；测试副本明确关闭 AVB 并使用 `-writable-system`，只作为已标记的 QA 系统，不能证明真实硬件或设备认证结果。源码不携带这些镜像。

每轮仍为新 AVD、独立数据分区、无运行快照、新安装。Android ID 由新系统数据生成；系统查询侧与自有 APP 读取侧分别记录哈希，作用域不得混淆。设备型号须通过系统读取及自有 APP 回执核对。操作只覆盖固定属性与文件，保留 CPU 架构、系统版本和 APK 兼容性。

代理按用户最新要求使用按请求轮换模式；取消 APP_OPEN 的专用出口 IP 探测、去重和每日流程中的自动代理探测。保留代理配置、认证/传输错误处理及无直连回退。独立手动 PROXY_CHECK 保留给管理员排错。新观察不得填造 proxyObservedIp；“已配置代理”和“已验证某出口”分别表达。

## 自有 APK 与账户上报

包名固定，原生界面只展示测试状态、账户和观测信息，无广告、业务媒体或注册表单。每次新安装首次启动生成并持久保存 installationId、请求幂等键及随机种子；同一安装重启和网络重试保持相同请求，不因住宅代理 IP 轮换创建第二条账户。

APP 读取自己作用域的 Android ID、Build 型号和系统版本，立即用明确的本轮测试 UA 发起原生 HTTP 请求。中台保存收到该请求的 User-Agent，比较 APP 声明值与本轮配置。自有客户端不加载 WebView，旧兼容字段 appliedWebViewUa/defaultWebViewUa 明确填 NOT_COLLECTED；uaMatched 仅表示实际原生请求 UA 匹配，不证明任何 WebView 或第三方 APK 的 UA。UA 包含真实系统观测及本次安装的随机测试标记，不把它描述为真实浏览器身份。

APP 不额外查 IP。中台从可信反向代理后的请求连接获取来源 IP，不接受 JSON 内声明的 IP 或任意客户端伪造的转发头。依据来源 IP、APP Android ID 和安装幂等键，以服务端密钥 HMAC 生成 6–10 位小写英文用户名；密码为 8–12 位、同时含英文和数字的密码学随机值。密码与原始 Android ID 加密保存，普通列表不返回密码；显式查看必须登录并审计，响应 no-store。

上报需要限定本次测试的短期、单次安装绑定令牌。令牌不得使用管理员/节点长期凭据，不出现在命令行、日志或 Git；Agent 在安装后通过 APP 私有测试文件注入。首次请求在数据库锁内创建一条记录，令牌绑定 installationId 和请求摘要；超时重试返回同一账户，不重复创建。正文变化、跨安装复用、过期未使用、停止后的新建、未知/撤销令牌均拒绝。已经创建的记录保留；未知结果通过原幂等键查询/重试，禁止换键再建。

## 中台与验证

新增“测试数据”菜单，显示时间、执行服务器/轮次、用户名、该账户创建请求的出口 IP、APP Android ID 哈希、实际型号、实际 UA、镜像档案及上报状态，并有刷新、筛选及显式密码查看。账户数与普通第三方 APK 的 APP_OPEN 完成轮数分别统计。APK 下载入口仅提供已构建、校验的自有 APK；不把自有 APK 结果当作第三方注册成功。

运行时 Schema、正反例及 HTTP 清单先于实现。验证包括代理请求轮换下的幂等、两并发令牌分配、停止/过期、伪造 IP/UA、密码脱敏、原 APK 字节不变、三个实际型号与不同 APP Android ID/UA、自有 APK 前台停留和清理，以及中台菜单真实浏览器检查。契约、lint、typecheck、test、build 通过后才发布；镜像原型和实际回执单独记录，未执行不宣称完成。

## 1.14.1 上报时序修复

真实三轮验收发现前台打开与清理均完成，但账户上报为零；诊断中冷启动 WebView 延迟了请求准备。自有 APK 1.0.1 移除这项前置初始化，原生请求立即发起；每轮停留仍为 10 秒。客户端将固定状态写入私有文件，Agent 在清理前读取，仅向时间线发送固定白名单消息，不包含账户、令牌、设备原值或异常原文；HTTP 200 表示收到本次回执，其他状态保持未确认或明确错误，不改变 APP_OPEN 的完成数含义。

下载与来源页面链接绑定发布 APK 的 SHA-256，公开查询仅接受已发布的固定哈希。修改后的 APK 是新的发布产物，各轮不再修改其字节。旧包、旧批次与零上报记录保留。

自有客户端日志只接受对应任务 HOLDING 阶段；“账户已上报”还必须有该任务的实际 TestRecord，不作为独立账户证据。下载日志仍只接受 DOWNLOADING 阶段。网络异常表示响应尚未确认，不能直接判定没有创建账户。
