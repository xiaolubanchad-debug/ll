# 1.13.1 独立模拟器准备优化与步骤耗时

版本 1.13.1，Agent 0.11.1，2026-10-30。先升级中台，再部署执行端。沿用 1.13 的两路上限、N/M、每日额度、节点锁、停止与清理回执；不改变旧注册历史。

每轮继续创建独立 AVD 和全新数据目录，不使用快照、已启动的共享模拟器或预装产品数据。每轮建立独立代理桥并检查代理；模拟器从启动时即配置该代理，无直连回退。代理检查与 AVD 创建、安卓冷启动可以重叠；代理未通过前不得返回可安装的会话，失败或停止须取消并等待准备分支退出，然后清理全部本轮资源。关闭失败仍隔离节点。

APP_OPEN 设备检查将固定的 getprop 只读属性合并读取，与独立的 Android ID 查询并行；只保存白名单属性及原有作用域，不记录完整属性输出。安装前仍核对 APK 大小和 SHA-256，但不重复解压与解析已经通过完整结构、CRC 和清单检查的相同字节；缓存读取保留完整 APK 检查。哈希不符、非普通文件、符号链接或检查期间文件变更不得安装。旧表单注册路径不改变。

TASK_FINISHED 可增加 openTimings，结构为 `{version:1,totalMs,steps:[{name,startedMs,elapsedMs,outcome}]}`。仅 APP_OPEN 使用；旧节点可省略。name 固定为 PROXY_CHECK、AVD_CREATE、EMULATOR_BOOT、DEVICE_CHECK、APK_VERIFY、APK_INSTALL、APP_LAUNCH、FOREGROUND_CHECK、FOREGROUND_DWELL、CLEANUP。时间均为相对本轮 openApk 入口的单调时钟毫秒，非负整数；totalMs 最大 3600000，每项不超过 totalMs 范围，名称不得重复，最多 10 项。outcome 为 SUCCEEDED、FAILED 或 CANCELLED；只表示步骤调用结果，不代替 APP_OPEN 完成证明。失败与取消只报告实际执行的步骤；冷启动包含等待系统启动完成。准备并行时步骤时间可能重叠，不得相加冒充总耗时。总耗时不含此前读取缓存，包含阶段回执与清理等待。

APP_OPEN 启动使用固定 am start 命令提交启动，不再等待 am start -W 的 Activity 完成加载回执；随后最多 30 秒、约 250ms 间隔检查目标包是否处于前台，失败或超时不得计为完成。旧表单注册仍使用 -W。前台停留仍从首次明确前台确认后计时，至少 10000ms，保留原有持续前台采样和清理成功条件；不表示 APP 内容已加载或完成注册。计时不采集 APP 内容、截图、账户、代理凭据或目录。中台 timeline 的 TASK_FINISHED 可返回通过同一运行时 Schema 检查的 openTimings，页面以中文名称展示步骤、耗时和并行提示；旧事件不补造子步骤。

正例：代理检查开始于 0ms、耗时 3000ms，冷启动开始于 1000ms、耗时 35000ms，两者都成功后才安装；两个步骤合计大于墙钟时间是合法重叠。反例：负时间、未知步骤、重复步骤、步骤结束超过 totalMs、任意文字/凭据、在非 APP_OPEN 批次上报耗时、代理未通过即安装、清理未确认即结束，均拒绝或停止。

验证：运行契约正反例、lint、typecheck、test、build；准备并行的失败、取消和清理竞态需覆盖。EC2 用自有 APK 验证两路独立资源和停留清理，再发布并部署；以同一七猫缓存 APK、同一 EC2、两并发、10 次完成对比优化前后。每组总尝试最多 12，保留全部失败；实际 APP 打开后不为测速重放。分别报告墙钟、单轮平均、各步骤和清理，不能用 20 次总时间直接对比 10 次总时间。CPU/核数参数实验仅使用自有 APK；未证明收益和兼容性的参数不作为默认值。

候选验证已通过 212 项契约检查、lint、类型检查、构建及全量 PostgreSQL/SQLite/Chromium 回归；覆盖准备并行失败、取消等待、前台确认超时、文件变更拒绝及历史日志兼容。Ubuntu 26.04 / KVM 自有 APK 两路真实安装、启动、停留和清理通过，步骤均有单调计时，未调用账户或内容读取。自有 APK 的一核对比未取得收益，默认保留两核。签名发布、生产部署及七猫实测另以运维回执核验，不把启动完成描述为注册成功。
