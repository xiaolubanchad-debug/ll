# 1.16 系统审计与交互整理

本轮按当前产品流程审查 web、control-api、部署 Worker、Agent、automation、配置/节点契约和测试入口。审计不等同于外部渗透测试或所有第三方 APP 的适配保证。自动化回归、真实部署及线上检查分别记录，不以历史测试替代本次执行。

| 发现                                              | 影响                                 | 本轮处理                                           |
| ------------------------------------------------- | ------------------------------------ | -------------------------------------------------- |
| 新向导已采用 APP_OPEN，旧配置编辑器仍主推注册流程 | 同一配置在不同入口出现互相矛盾的操作 | 当前配置编辑统一为打开停留，旧配置显式转换为新版本 |
| 服务器列表只能点管理，开始/停止散落在任务中心     | 操作繁琐，不易确认实际占用           | 服务器行集中配置、部署、开始、停止、检查、日志     |
| 已绑定任务的配置不能再次接入另一任务              | 另一服务器复用配置时报已绑定         | 服务器配置页明确复制草稿为独立任务，保留原任务归属 |
| 已完成任务的普通开始没有新增轮次                  | 容易误认为再次运行成功               | 明确新增一轮确认，继续沿用幂等和数据库锁           |
| 工作台主要展示旧注册统计                          | APP 打开完成和真实自有账户容易混淆   | 增加真实 APP_OPEN 汇总，旧统计放历史区             |
| 页面仍显示 1.8、旧 Agent 版本和“注册能力”         | 与当前部署状态不符                   | 更新当前入口文案，历史结果保留原语义               |
| 服务器没有实时 CPU 使用率采样                     | 不能照截图虚构 CPU 百分比            | 明示未采集，心跳只展示已有内存总量                 |

继续保持：单模拟器、代理无直连回退、每 APP 前台 10 秒、整组清理后换设备、每日缓存及安全清理、未知结果不自动重试、真实回传与打开完成分开、内容证据隔离、秘密加密及脱敏、签名发布与 SSH 主机身份核验、节点占用与停止回执。保留旧注册引擎和历史接口用于已有数据与人工核验，不再作为日常新建入口。

日常操作：服务器 → 选择或填写任务配置 → 保存 → 开始；同一行停止、查看日志。尚未部署时先同一行部署。详细历史与配置版本仍可从任务详情进入。

验证边界与待观察项：三日真实验收为独立验收项，尚不能以本轮 UI 回归代替；CPU 使用率采集没有实现；第三方 APP 的自动建账行为仍只能由产品侧证据确认；备份恢复与长时间资源使用需要各自的运维演练，不能据此审计声明已经全面验证。

本轮本地检查：242 项契约检查、lint、全工程类型检查和构建；既有登录/SSH/部署/下载/代理/执行状态机回归；真实 PostgreSQL 的新统计与实际占用读取；历史记录与任务控制回归；登录、配置保存、日志、测试数据和设备数量向导；5 项新增服务器交互检查及桌面/窄屏布局。生产依赖 npm audit 未报告已知漏洞。旧界面测试定位随新布局调整后分段补齐回归；本轮未修改或重新执行原生测试 APK 的网络发送实现，也没有新发起第三方 APP 注册。

发布范围为中台页面、管理查询及契约；执行节点继续使用已有 Agent 0.13.3 和已验证安卓环境，无须为此重新安装 SDK。线上任务的手动停止状态必须保留，定时验收不能因升级自动恢复。
