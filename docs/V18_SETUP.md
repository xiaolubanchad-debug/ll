# 1.8 任务中心使用说明

2026-10-29。中台 1.8.0，继续兼容已部署的 Agent 0.6.0；不需要重装 EC2。

## 第一次配置

登录默认进入任务中心，点击“新建任务”。第一步填写名称、网站 URL 和图标 XPath；第二步选择服务器及已保存代理，默认下载并注册、自动寻找注册入口，也可以只下载；第三步填写所有 APK 合计成功目标和总尝试上限。每天自动执行为可选项，时间默认北京时间 00:05。保存不会访问网站、启用计划或注册。

只有一个可用服务器或代理时自动选中。可在向导中新增代理，凭据保存后清空，不进入 URL 或浏览器持久存储。已有方案从第一步“从已有方案接入”选择，不需要重填；已被其他任务接入的方案会拒绝重复绑定。若该服务器的旧每日计划已开启，先在高级操作中关闭旧计划。

## 日常操作

任务卡片固定显示“开始任务”“停止任务”“编辑任务”，同时展示当前阶段、成功/目标、尝试/上限、当天 APK 数和下次自动时间。

开启的任务负责管理所绑定服务器；如需从高级入口手工执行或部署，请先停止此任务，避免在下载和注册衔接时抢占节点。

开始任务会立即检查代理，再自动关联当天下载并注册，不需要手工选择版本、执行类型或下载批次。有匹配的当日下载时复用；有界下载失败或缓存缺失不会自动绕过每日限制重新下载。网页与 APP 使用手机屏幕，注册沿用独立模拟器环境及每轮清理规则。自动识别无法可靠找到入口时提示待适配，可直接进入注册规则并查看失败详情与截图，不能把识别能力当作所有产品都已联测。

停止任务同时关闭后续每日自动执行，并等待当前批次停止及清理确认。后台离线或结果未知时保留等待/核验状态，不虚报已停止。浏览器关闭后，任务仍由中台后台管理；重新打开会读取数据库中的状态。

停止后再次开始保留本轮已成功数量和已消费尝试，新尝试只使用剩余额度；已提交注册不回放。节点清理确认后，新尝试可采用刚保存的注册配置，历史执行快照不变。未知必须先在执行详情核验账户结果并按既有流程确认节点清理，再显式开始。已达到目标或尝试耗尽时不自动增加账户；“更多操作 → 新增一轮”会说明新的 N/M，并要求明确发起。

“只关闭每日自动（当前继续）”只影响未来计划；普通停止则同时停止当前流程。任务归档要求已停止且无待核验执行，恢复不会自动启动。

## 编辑和历史清理

保存任务自动生成新的不可变配置，不要求日常选择版本。当前执行不被编辑打断；修改下载规则后若当天已经下载，则今天继续使用原来源，提示下载规则次日生效。更换节点需要先结束活动轮次，当日再次执行需显式新增一轮。

任务详情的“本任务配置历史”可查看引用、归档、恢复、删除及“用此版本编辑”。恢复历史内容会另存新配置，不覆写原记录。系统设置和服务器页面提供程序发布历史管理；旧方案编辑页也提供历史管理。

无引用的旧配置版本、空方案和程序发布登记可永久删除；有执行、计划、任务、节点或历史引用的记录只能归档。当前配置或未结束执行不允许归档，页面显示引用情况。批量归档与恢复一次最多 100 项，整批校验失败时全部回滚。删除登记不会删除服务器文件、账户、证据或发布安装包，文件清理为后续独立范围。

旧任务方案、手工下载/注册、旧每日计划位于侧栏“高级操作”。历史执行地址仍有效，完整日志和账户证据沿用原有鉴权与审计。

## 发布与验证边界

升级先检查无活动执行和部署并备份数据库；应用 202610290002_v18 迁移，再更新中台 API、Worker 和 Web。保留旧配置、计划与执行历史，不迁移为自动开启的统一任务。

验收使用隔离 PostgreSQL、真实 Chromium 和自有合成任务记录。覆盖幂等保存、重复开始、并发调度、代理失败、下载关联、全局额度续跑、未知不重试、过期调度拒绝、停止等待回执、配置切换、每日时间边界、版本引用及批量回滚，浏览器验证三步向导、主按钮、历史删除、刷新和手机布局。节点执行及回执在新增编排测试中模拟；APK 原生安装注册继续沿用独立记录的 0.6.0 验收，不以本次中台测试冒充真实产品注册。生产部署只读验证，不自动开始产品任务。
