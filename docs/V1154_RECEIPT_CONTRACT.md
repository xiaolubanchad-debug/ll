# 1.15.4 自有账户的只读回执核对

执行端 Agent 0.13.3，自有客户端 1.1.2，保留单模拟器、每台随机多个 APP、10 秒前台停留、代理与原始网络日志。真实观察到中台已保存账户但 APP 未拿到响应，不能把客户端超时等同于未回传。

客户端在 Activity 首次启动时初始化并发送同一持久请求，测试广告/公告只控制 UI，不再次初始化请求。覆盖 1.15.3 的时间参数：总预算 10000 毫秒、每次最多 3500 毫秒、最多 4 次串行尝试；仍受停止和卸载约束。为代理 CONNECT 后的 TLS 与响应保留时间，避免每次总期限与代理 2500 毫秒期限相同。预算不会延长 APP 的 10 秒停留，APP 清理时未完成仍保持未知。1.1.2 的回传和套件清单同时加入 Schema 白名单，旧版本仍可读取；不把加大预算等同于住宅网络必定成功。

新增 POST /agent/tasks/{taskId}/test-receipt，NodeBearer，TestBootstrapInput 上下文，返回严格 TestClientReceipt={received:boolean}。必须核对当前节点、delivery、fence、有效租约、已接收的活动批次、HOLDING 阶段、自有客户端配置及包名、对应 enrollment 的归属。仅查询当前任务是否存在已提交的 TestRecord，不创建账户、不重发 APP 请求、不延长租约，不返回账户、设备原值、IP、UA、令牌或其他任务信息。停止、旧 fence、跨节点、第三方 APP、过期和终态请求拒绝。

客户端不是 HTTP_200 且属于网络/未知响应时，在 APP 已关闭卸载并确认清理后，执行端可进行一次最多 2 秒的只读查询。保留原始“网络响应尚未确认/上报结果尚未确认”等日志。received=true 时追加固定日志“自有测试 APK：中台已确认收到（APP响应未确认）”；该日志也必须有同任务真实 TestRecord 才允许入库。没有记录、查询失败、无效正文、停止或清理失败不追加确认。HTTP_200 的已确认路径不额外查询；明确 4xx 拒绝不查询。

此查询不增加 APP 前台停留，不重开已卸载 APP，不增加 N/M、不生成新用户名，不将 APP_OPEN 解释成账户成功。完成数继续依赖打开停留与清理；账户数依赖真实记录。旧批次与旧未确认日志不回填或改写。旧 Agent 的原有行为继续可用，新端部署前先升级中台。

正例：APP 请求已建账、回包丢失、APP 清理完成，只读查询看到原记录并追加中台确认，仍仅一条账户。反例：查询本身建账、用另一任务记录确认、未清理就查询延长停留、停止后查询、received 字段附带密码或伪造确认日志，均拒绝。测试分别验证端点鉴权/归属/阶段与零创建、执行顺序/预算/无重发、日志及真实 Android。持续验收同时报告客户端未确认数、经中台核对确认数和最终仍未确认数，不能隐藏网络异常。
