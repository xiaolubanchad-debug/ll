# 1.22 任务恢复修复

修复手动继续任务保留旧 Agent 发布快照的问题。新 generation 在空闲、在线、已部署和无未决核验的前提下使用节点当前版本，保留全部已用次数、下载来源和旧执行记录。调度遇到版本变化时关闭本次任务并明确提示点击开始继续，不再无限等待 NODE_NOT_READY。

服务器页显示等待原因；尚未生成新批次时不再跳到旧的待核验记录。已确认停止的历史批次不再展示遗留 Task 或设备会话为当前执行状态，原始历史和清理回执保留。

现场只排查元数据并通过正常停止接口关闭卡住请求。后台已收尾为 STOPPED，节点无运行批次、无隔离占用，原有完成数和尝试次数保留。没有运行网站下载、APK 安装或打开流程，没有修改历史执行版本，没有清零额度。

按用户要求，代码未运行自动测试、lint、类型检查、构建或契约检查，不声称测试通过。中台版本 1.22.0；Agent 本次不变，仓库仍包含尚未部署的 0.17.0 人工元素检查。代码提交不等于线上代码更新。

中台和 EC2 代码尚未部署。原发布门禁保留；免测试发布例外此前被自动审批拒绝，原因是未获明确授权放宽发布门禁，本轮未绕过。当前线上仍是中台 1.20 / Agent 0.16.0。用户可以查看已停止状态；版本恢复修复需要部署后生效，部署前再次开始旧任务仍可能遇到原问题。
