# 1.22 任务恢复修复

修复手动继续任务保留旧 Agent 发布快照的问题。新 generation 在空闲、在线、已部署和无未决核验的前提下使用节点当前版本，保留全部已用次数、下载来源和旧执行记录。按用户进一步要求，调度遇到版本变化自动衔接，保持任务开关开启，不因升级自动停止，也不再无限等待 NODE_NOT_READY。增加可选缓存文件选择，便于只复用指定 APK 实跑，不重新下载。

服务器页显示等待原因；尚未生成新批次时不再跳到旧的待核验记录。已确认停止的历史批次不再展示遗留 Task 或设备会话为当前执行状态，原始历史和清理回执保留。

现场只排查元数据并通过正常停止接口关闭卡住请求。后台已收尾为 STOPPED，节点无运行批次、无隔离占用，原有完成数和尝试次数保留。没有运行网站下载、APK 安装或打开流程，没有修改历史执行版本，没有清零额度。

初次提交按当时要求未运行测试；用户现已明确改为测试后发布。当前补充契约、任务恢复、缓存选择、人工元素事件和页面交互回归，完成后记录实际结果。中台版本 1.22.0，Agent 0.17.0。SDK、镜像、型号池不变，发布沿用正常门禁与环境基线。

上线和 55 缓存 APK 十轮实跑结果待本轮完成后补充；未实际完成前不声称通过。真实验收与本地模拟安装器测试分别记录。
