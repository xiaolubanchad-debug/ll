# 1.9.2 导航站跳过与 APP 注册入口

2026-10-29，Agent 0.7.2。配置与节点协议继续为 1.0，HTTP 契约版本为 1.9.2；中台须先升级再部署新 Agent。

## 导航目标

点击图标后的已加载手机页面，只有出现明确的多应用导航结构、且没有可见的 APK 文件链接时，才可记为 `SKIPPED/NAVIGATION_SITE`。自动下载仍优先处理，等待至少 1.5 秒；网络错误、空白页、普通下载页及无法判断的页面继续沿用失败规则，不能一律当作导航站。不能递归点击导航站里的其他应用。

导航结构的正例：至少 8 个不同 pid 的可见 jgg-item 图标；或具有导航/应用推荐标题、至少 8 个图文入口和至少 4 个不同外部站点。反例：有 APK 链接的产品下载页；普通文章带若干外链；请求失败后空白页。

跳过项不计入下载成功、注册成功或注册尝试。批次保留 SKIPPED 记录，继续后续图标；有 APK 且无真实错误的下载批次可完成，全部为导航站时返回 `NO_APK_AVAILABLE`，中台结束本轮且不启动模拟器。

原生 APP 若在连续稳定快照中明确显示多应用导航结构、没有输入框或注册/登录/个人入口，可在提交前记为 `SKIPPED/APP_NAVIGATION_ONLY`。普通 APP 找不到入口仍为待适配，不能用跳过掩盖识别故障。跳过结果必须无账户和提交意图；独立模拟器清理确认后才能继续。每个实际启动的尝试仍计入 M，并在清理后继续下一个已下载 APK；若本批次的所有文件都已明确确认为导航壳，则以 NO_REGISTERABLE_APK 结束，不再重复轮转。清理失败和未知提交仍立即隔离。

## 注册入口与表单

入口识别接受明确的注册、点击登录、未登录、个人中心等常见短语，及可点击控件上精确匹配的注册/登录/个人页资源 ID。不得用模糊子串点击充值、购买、注销或第三方入口。相同目标的父子候选可合并；多个不相干候选继续停止。

可见范围由活动窗口界限约束，完全在屏幕之外的节点不参与识别。WebView、滚动容器的全屏点击属性不得使整页只读文字变成按钮。无 hint 的用户名密码框可在唯一相邻标签和完整表单结构得到确认后绑定；重复控件 ID 只允许受当前快照约束的精确 XPath，页面变化仍需重新核验。WebView 登录表单旁的注册链接属于导航，不得当作注册提交。

正例：原生“点击登录”进入登录页后点击“注册新账号”；账号标签旁的空输入框与两个明确密码框得到唯一绑定。反例：离屏广告中的“注册”；重复标签无法区分字段；登录按钮与注册链接同时出现时直接提交登录表单；普通欢迎页作为注册成功。

唯一提交、未知结果不重发、账户加密、证据脱敏和节点回执沿用既有契约。测试 APK 与实际产品验证分别记录，实际成功仅计有效 APP_UI 证据。

## 自动身份单独观察

用户已确认：无需用户名密码、APP 自动显示的身份单独统计，不计入 N。仅进入首页、欢迎页、设备标识或普通游客提示均不足以确认身份；须在当前 APP 的账号/个人页面读到唯一、明确标注的用户 ID/UID。记录的是身份观察次数，不承诺后台创建了新账户，也不冒充系统生成的用户名密码。

recognition 可附 automaticIdentity，包含 GUEST/APP_ASSIGNED、标识摘要和 APP_UI_ONLY 范围，禁止传输原始 ID。截图对应 ID 区域必须遮挡。此字段本身不能让任务成功，SUCCESS 仍要求唯一提交及注册成功证明；各批次摘要新增 automaticIdentityCount，由有效任务记录统计。无注册入口但观察到自动身份时可 SKIPPED/APP_AUTO_IDENTITY，保留脱敏证据并继续后续 APK；所有资产均为导航壳或仅自动身份时以 NO_REGISTERABLE_APK 结束。已提交与未知结果不能转为此类跳过。

正例：个人中心显示“游客”及唯一 UID，记录 1 次自动身份观察、注册成功数仍为 0。反例：打开首页就记注册成功；把用户 ID 写入普通日志；用自动身份绕过已提交结果核验。

设备检查接受 1–16 位、非全零的十六进制 Shell Android ID，不要求固定 16 位，也不填充或改写观测值。AOSP SettingsProvider 使用 Long.toHexString，合法值可能没有前导零；来源：[SettingsProvider](https://android.googlesource.com/platform/frameworks/base/+/main/packages/SettingsProvider/src/com/android/providers/settings/SettingsProvider.java)。此值仍仅为 SHELL_NOT_APP，不代表 App 标识或真实设备。正例：15 位合法十六进制值；反例：null、全零、超出 64 位或含非十六进制字符。

## 验证范围

自有网站验证导航站跳过后继续下载 APK，并通过真实 PostgreSQL 和节点事件确认全部导航目标不会启动安装。自有 API 测试验证自动身份独立计数、没有账户和提交意图，以及未执行配额的结束规则。

Ubuntu 26.04 / KVM EC2 已验证三个自有 APK：经登录页进入无 hint 的用户名及双密码注册表单，仅提交一次且取得成功界面；游客 UID 单独观察、截图遮挡且零提交；多应用导航页明确跳过且零提交。三个场景均确认模拟器清理完成。该验证使用自有服务和测试代理，不代替真实产品及住宅代理验收。
