# 1.23 网页代理与故障恢复

中台 1.23，签名 Agent 0.17.3。下载、打开测试和历史账户记录保留原有业务含义。

## 下载网络与目标发现

所有新建且需要访问网页的批次（每日下载、手动重下和旧版单次入口）必须使用支持本规则的签名 Agent，以及不可变配置引用的有效 HTTP 代理。仅下载也需要选择代理。无代理、吊销或节点版本不支持时拒绝创建。代理秘密只向已确认、仍持有租约和 fence 的节点下发。已有配置仍可读取，缺代理的方案需保存新版本后才能下载。已下载的当天资产仍可直接复用。旧批次的历史记录保留，升级前须停止正在运行的旧下载。

Chromium 的来源页、跳转页、弹窗、子框架和文件请求共用同一个认证 HTTP 代理。Agent 使用本地转发层保留目标网络限制与 DNS 地址固定。允许的目标通过代理访问，代理不可用时拒绝下载，不切换到直接连接。代理口令、地址、完整 URL 和网页正文不进入失败日志。目标无法访问、代理连接失败、代理认证失败及安卓环境确认失败分别记录。此规则适用于浏览器 HTTP(S) 请求。

来源页确认安卓环境成功后才发现和点击目标。初始无匹配时最多等候 3 秒，随后重新读取 XPath；人工检查等待完成后再确定点击名单。不支持的链接协议按单个候选跳过，其他合法目标继续。按文件名和冻结摘要复用 APK 时，允许在同日查找仍有效的同名副本。已有的下载限额、锁及文件校验保持。

正例：仅下载任务选择已保存代理，安卓浏览器通过该代理访问首页、跳转并接收 APK；延迟出现的目标可点击；一份同名文件失效时仍可用完好的同日副本。反例：旧 Agent 执行新下载、无代理直连、安卓确认失败后点击、绕过网络限制或使用不同摘要副本，均拒绝。

## 故障恢复与发布

续跑批次在首个 APP 前再次发生整机清理失败时，仍登记同样的 30 秒恢复。必须取得绑定当前交付的清理回执和其后的空闲心跳；只继续原队列的未执行位置。手动停止、脏设备、跨日及未知提交保持原有约束。

清理回执先写入 Agent 本地待传记录，超时后按退避补传，确认后才清除。过期交付的补传不能改变后续批次或认证 boot。旧交付补传失败保留证据并按交付退避，中台继续通过槽位、隔离和租约决定是否允许新领取。待核验的未知账户仍禁止自动重放。

下载取消与正常收尾共用同一个浏览器关闭回执。下载中停止时先关闭浏览器，再清理代理和临时目录，确认后上报停止。反例：并发关闭同一浏览器并把第二次关闭报错当作清理失败。

登录先应用 IP 总额度，再处理用户名额度。被 IP 总额度拒绝的请求不建立用户名桶。发布测试选择覆盖下载发现、安卓浏览器、缓存和 Agent 补传回归；签名、环境校验及新心跳门禁保持。

正例：清理回执首次超时后补传成功，真实空闲心跳到达后恢复；旧记录持续拒收时仍可向中台请求领取。反例：未确认清理便释放槽位、由旧交付覆盖新批次、自动重试未知账户提交或因补传失败删除原始记录，均拒绝。

## APK 安装诊断

Agent 0.17.3 将 Android 明确拒绝按 APK 格式、缺少拆分包、CPU 架构、Android 版本、签名冲突、已存在、存储空间、系统限制和其他拒绝分类。设备离线、安装超时或没有可核验的回执单独显示。只记录固定错误代码，ADB 原始输出、路径、包名和异常正文不进入诊断日志。旧记录的通用 `APK_INSTALL_FAILED` 显示为安装失败且历史原因未保留。

明确拒绝且安装前后包清单一致时，仅跳过当前 APP，同机继续原队列。结果无法确认、包清单变化或无法核对时，必须先清理整机，再按原顺序续跑。任务表记录最终处理原因。若整机清理原因覆盖了安装错误，执行时间线仍可查看本次固定安装诊断。不会以重装、覆盖已有包、绕过 Android 安装限制或预先读取 APK 清单消除错误。

新建随机机型批次逐个 APK 判断可用机型。节点有至少两款已验证同时支持 ARM64 与 x86_64 的机型时，架构未记录的 APK 只分配到这组机型，包括同批也有已知架构的情况。已知架构的 APK 按实际兼容性选机，固定机型和既有续跑快照按原配置执行。此规则基于节点启动回执，不从 APK 文件名猜测架构，也不要求重下载现有文件。

正例：Android 返回 `INSTALL_FAILED_NO_MATCHING_ABIS`，任务显示架构不兼容，确认没有残留后继续下一个 APP。反例：仅 ADB 断开或超时就判定文件损坏，或未确认设备清洁便继续，均拒绝。

## 1.23.1 APP 启动兼容性

Agent 0.17.4 的 APP 启动停留根据 Android 前台应用及焦点窗口判定归属。同屏存在外包控件时允许等待和核对前台。安装后的包名仅用于归属判断，规则对所有 APP 一致。开屏倒计时、可见启动遮挡、暂时失去焦点和前台恢复共用最多 20 秒的等待额度。恢复后重新开始连续 10 秒前台采样；从启动回执起最多 40 秒，包含中断前已消耗的停留时间。确认稳定的普通页面直接开始停留，无需等满。只执行唯一、复查后仍属于目标 APP 的明确跳过或关闭控件。

启动入口缺失、启动回执超时或被拒绝、系统窗口阻挡、其他 APP 未返回、倒计时未结束和窗口状态无法确认分别记录固定原因。清理仍按当前 APP 确认，整机清理失败遵循原队列及 30 秒恢复规则。原有历史错误和协议保持兼容；不传出页面、窗口标题、原始 ADB 输出或崩溃正文。

正例：倒计时或其他窗口在等待额度内消失，目标 APP 随后连续保持前台 10 秒，当前 APP 才完成；同屏外包控件没有抢占前台时允许继续。反例：持续停在权限、浏览器或商店窗口也计时、累计两段不连续的前台时间、点击外包控件或绕过完整性检查。缓存执行只使用选定的当天下载批次。

## 1.23.2 APP 前台观察日志

Agent 0.17.5 在 APP 启动停留的现有采样点汇总窗口观察，在清理前上报一条绑定当前 APP 的日志。日志包含是否观测到目标 APP 获得焦点、最后一次采样的窗口类别与可识别的包名，以及从发出启动流程到各次变化的相对时间。最多保留首个采样及前七次变化，最后一次采样单独保留。同一包名与类别连续出现时合并，读不到窗口则标为无法确认。启动回执失败且尚未开始轮询时，可在清理前短时补采一次并注明仅为启动失败后的快照。

中台只在 APP 启动或停留阶段接受该日志，任务详情显示固定分类、经格式约束的 Android 包名及相对时间。旧节点、旧记录及现有成功判定保持兼容。正例：先观察到目标 APP，后来焦点落到桌面，显示两次采样的时间与归属。反例：将未采到目标视为已经证明它从未打开、写入窗口标题、网址、控件内容、截图或 ADB 原文。

## 1.23.3 启动期间的进程和窗口证据

Agent 0.17.6 从发出 Android 启动命令时开始采样窗口，包括等待启动回执的阶段。该阶段的采样在启动调用结束后停止，再接续原有前台观察。目标包默认进程及其冒号子进程的 `am_proc_start`、`am_proc_died` 和 `am_crash` 只在本次启动起点至清理前的时间窗内解析。每个事件只保留固定类别、主进程或子进程、PID 和相对时间。最多保留 16 条进程事件，并注明读取是否可用及是否截断。清理引起的进程退出不纳入启动证据。

正例：启动回执超时，但期间已经观察到目标窗口或进程，仍独立记录相应事实；Android 写入目标进程的崩溃事件后，可以显示系统确认崩溃。反例：根据桌面窗口、未读到事件或仅收到进程终止请求就断言崩溃；将其他包、历史执行、异常原文或清理引起的退出归到当前 APP。诊断不改变回执、清理和成功判定。旧日志仍可读。
