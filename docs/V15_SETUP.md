# 1.5 操作与验收

Agent 0.5.1，接口契约 1.5.1。规则见 [1.5 契约](V15_CONTRACT.md)。验收只要求通过代理操作手机 APP 并确认注册成功，画像与 App UA 不作为前置条件。新建模拟器仍不代表新的真实手机。

## 升级和使用

中台备份数据库、密钥和证据后，构建同一提交的 API、Worker、Web 与工具镜像，应用第五条迁移 202610280002_v15。数据库增加每日计划、日记录及批次目的、资产快照、配额和实际尝试计数；旧批次保持 LEGACY，旧接口默认行为不变。执行节点需通过中台部署新的 DAILY_V1 签名发布，等待 Agent 0.5.1 在线及安卓就绪。部署 Worker 不增加每日计划或配置读取权限，调度由 API 的数据库事务执行。

任务页提供三种执行内容：仅下载当天 APK、复用当天 APK 循环注册、旧版单次流程。每日下载创建一次后，同日再次点击返回同一个批次，不重新访问来源。循环注册需要选择本服务器、本配置当天已结束的下载批次；注册配置可以是补充了代理或注册步骤的新版本，但网站 URL/XPath 必须一致。

代理在配置页加密保存，应用到草稿并保存为完整配置版本后可用于注册。独立“在 EC2 上检查代理”可以选择任意已保存代理，不要求先修改下载配置，也不会启动产品 APP。检查结果在任务列表显示，只证明本次探测出口。

1.5.1 取消端口预填，必须填写服务商提供的单个端口；如范围为 10000–10199，可先填写 10000。修正已保存代理时另存新版本，旧任务保持原快照。出口检测先访问 ipify，失败时最多尝试一次固定 Cloudflare HTTPS 检测地址，任一返回合法 IP 才成功；全程走代理并校验证书。TLS 中止或任务停止会结束当前连接，不悬挂，也不会直连回退。

页面修复补注册原先缺失的数字输入组件及样式，确保端口可见、可编辑；浏览器回归同时核对未填写时禁止保存，以及实际请求携带填写的端口。

注册流程仍按包名配置屏幕控件和明确成功标识。没有启用适配的 APK 不会猜测提交。循环填写成功目标 N 和尝试上限 M（1–1000 且 M >= N），按候选 APK 顺序轮流执行，实际开始一轮才计尝试；代理、安装、启动失败也计入。达到目标时，剩余未执行槽位显示 QUOTA_NOT_USED；未知结果立即暂停核验，不能重发提交。

每日计划使用任务页上方选中的固定服务器、配置版本和发布。默认北京时间 00:05，新计划开关默认关闭；勾选开启并保存后生效，已过当天时间会补当天一次。关闭“下载完成后自动注册”可以只做每日下载；开启自动注册必须使用已应用代理的 FULL 配置。修改目标与配置不会改变已触发当天日记录的快照。每日记录显示下载、注册、等待占用或需核验的原因；关闭计划后等待活动任务安全停止的回执。

用户名以随机姓氏和拼音名组合生成，6–10 位小写字母；密码为 8–12 位字母数字。节点加密保存账户，并通过不可逆摘要避免本地生成重复用户名；抽样重名过多时有界报错，不能无限生成。产品侧拒绝或名称占用按明确失败计入尝试。账户查看仍需管理员显式审计操作。

## 验证范围

每日换包优先用“图标入口 PID”绑定模板；可从来源 XPath 或下载任务的“入口 PID”列核对。绑定后包名和启动页面自动从当天 APK/已安装包读取，无需逐日修改；控件包名前缀可使用 {packageName}。同一入口的新包继续复用界面模板；全新界面出现定位失败时停止并提示 FLOW_LAYOUT_CHANGED，先更新模板再执行。未绑定入口的旧精确包名配置继续兼容，不支持无范围的通配注册。

配置页“添加基础注册流程”提供包名、启动页面、输入框、提交按钮及成功/失败标识表单，应用到草稿后保存新版本；账户不用在表单填写。它支持同页注册及可选打开注册页、确认密码，多页面流程保留原配置并单独适配。控件定位必须按实际 APP 核对，不能直接启用示例。

契约检查包含新计划及执行计划正反例、禁止明文秘密和任意执行目的。真实 PostgreSQL/SQLite/Chromium 回归覆盖每日唯一下载、全 APK 共用 N/M、重复事件、旧环境关闭、新 UA 无验证入口不阻断、代理检查不启动 APP、自动下载与备用按钮、完整新日后清理旧包、下载失败保留旧文件、跨日停止、关闭计划后重启、停止及 UNKNOWN 不重放。

代理凭据、APK、账户、截图和生产执行证明留在受保护目录，不入 Git。实际 EC2 部署与住宅代理检查分别记录；产品 APP 的 ABI、控件及成功标识仍需按具体版本适配。自有页面或 Appium 故障注入通过，不能代替真实产品注册通过。新计划不会在升级时自动开启。

2026-10-28 本地验收：103 项契约检查、lint、typecheck、build 和 72 条测试记录通过检查（71 通过，Windows 跳过 1 条 Linux 专属清理用例）。包括同一入口绑定两种包名、模板包名前缀展开及保持配置不变、目标总数、换日、未知结果和基础流程表单。CI、签名发布、EC2 及实际代理检查以对应提交的私有记录分别证明。

1.5.1 本地回归：同样的 103 项契约检查、lint、typecheck、build，以及 76 条测试记录（75 通过，Windows 跳过 1 条 Linux 专属清理用例）。新增代理主站 TLS 重置后切换、停止握手、无效/重复 IP、重定向与过大响应，以及浏览器实际填写端口和核对保存请求。EC2 的修复实现已用实际代理检查通过；常驻 Agent 发布与产品注册仍按各自的执行记录验收。
