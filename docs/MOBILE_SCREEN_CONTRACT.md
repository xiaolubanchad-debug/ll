# 移动端屏幕执行契约

版本 1.4.1，日期 2026 年 10 月 28 日。对应 Agent 0.4.1。用户最新要求：所有模拟使用移动端屏幕。该增量改变网页默认渲染和交互方式，不改变 HTTP 路由、配置 schemaVersion=1.0 或节点协议 1.0。

## 执行规则

1. 网站发现、XPath 图标定位、落地页和下载使用固定 Playwright 版本提供的 Pixel 7 手机配置：竖屏视口 412 × 839 CSS 像素、屏幕 412 × 915、像素倍率 2.625、移动端布局和触屏。默认 UA 使用该版本的 Android 移动浏览器 UA。新窗口和同页跳转必须继承同一上下文。
2. 来源图标和落地页下载控件通过触屏 tap 操作；不得仅替换 UA 后继续使用桌面视口或鼠标事件。下载监听先于触控操作建立，覆盖直接下载、落地页触控下载及落地页自动下载。
3. 已保存的 browserUserAgent 非空时继续作为显式浏览器 UA 覆盖，以兼容现有配置；它不会关闭手机屏幕及触屏。需要网站按 Android UA 分流时应留空使用默认值，或填写移动端 UA。此字段始终不代表 APK 的请求 UA。
4. APK 安装、启动和注册继续在 Android 手机模拟器中执行，使用手机设备 profile（当前已验收 Pixel 6）及原生控件定位。服务器无桌面、浏览器 headless、模拟器 no-window 均不改变其虚拟手机屏幕；本增量不提供实时屏幕串流。
5. 网页手机配置只用于下载，不作为每轮 APK 注册的设备身份。App 实际型号、标识、UA 和代理出口仍须按 P3 证据表达，不能从手机屏幕、AVD 名称或浏览器 UA 推断。

## 正反例与验收

- 正例：只在手机布局出现、仅响应触控的来源图标和落地页控件可以完成下载；弹出窗口及同页自动下载均收到手机环境。每个测试入口只有一次来源触控、一次 APK 请求。
- 正例：显式自定义浏览器 UA 保留，同时网页视口、屏幕和 touch 能力仍是手机配置。
- 反例：只改 UA、仍使用桌面尺寸；来源为手机、弹出的落地页恢复桌面；以鼠标事件代替触控使 touch-only 控件不响应，均不满足本契约。
- 反例：将默认网页 Pixel 7 UA 描述为 APK 请求 UA 已受控，或将模拟器描述为新真实手机，均不满足本契约。

正式回归使用自有页面、真实 Chromium 和结构校验用 APK，核对页面实际 screen/viewport、touch、UA、触控事件、请求计数及清理。该检查不安装实际产品、不注册真实账户。每日 00:05 调度、N/M 配额及缓存清理仍以 [1.5.0 需求](DAILY_DOWNLOAD_AND_REGISTRATION_REQUIREMENTS.md) 为待实现范围。

2026-10-28 本地验证：92 项契约检查、lint、typecheck、build 和完整回归通过；59 条测试记录中 58 条通过，1 条 Linux 专属进程清理测试在 Windows 跳过。新增测试包含默认 Android UA 及显式 UA 两种配置、每种配置的五条手机下载路径，并确认清理完成及持久 HTTP 连接不重复注册 socket 清理监听。实际发布、EC2 部署及产品注册分别记录验证，不能用本地通过替代。
