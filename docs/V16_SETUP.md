# 1.6 自动识别注册入口

Agent 0.6.0，契约 1.6.0。规则见 [自动识别契约](V16_CONTRACT.md)。已配置的手工注册流程优先；未配置流程的当天 APK 可尝试寻找自己的注册入口。系统支持常见中英文入口和原生用户名、密码表单，不承诺覆盖任意新 APP。

## 配置与操作

1. 升级中台并应用迁移 202610280003_v16，通过中台部署具备 AUTO_REGISTRATION_V1 的签名发布，等待 Agent 0.6.0 就绪。旧配置和旧批次保持原行为；新功能默认关闭，升级不自动开启计划或注册。
2. 在“配置校验”载入已有配置，将已检查的代理应用到草稿，保持 FULL 模式。
3. 展开“自动识别注册入口”，开启自动寻找；可启用本地图片入口识别，设置导航步数及寻找/核验时限。应用到草稿，再保存新版本。已有手工流程保留。
4. 先下载当天 APK，再选择同一配置的循环注册和当天下载批次。建议首次设置成功目标 1、尝试上限 1，核对实际 APP 的结果与脱敏截图后再调整配额或每日计划。
5. 任务显示“寻找注册入口”，完成后可查看识别方式、路径复用状态、导航次数及是否保存成功路径。出现待适配时结束当前批次；未知结果暂停核验，均不重复提交。

页面控件优先；图片入口在 EC2 本地用 Tesseract.js 7.0.0 和固定 npm 语言包识别，截图不上传外部识别服务。语言模型在部署时随锁定依赖安装；业务运行时仅从本地目录读取，不下载模型。图片表单输入框、手机号/邮箱/验证码、无明确成功标识、歧义或未知流程仍需手工适配。

## 数据与验证范围

学习路径按来源、入口和手机配置分区，节点 SQLite 加密保存；只在注册成功证据和清理均确认后保存。每轮重新核对页面，不直接重放旧坐标；新包名可复用同入口路径，界面变化则重新识别。迁移只增加任务识别摘要；不增加 Worker 对配置、账户或模板的权限。

验证分别覆盖：契约及正反例；页面识别、真实中英文 OCR、受控 Appium 边界、真实 PostgreSQL/SQLite/Chromium；EC2 上的自有 Android 测试包；实际产品 APP。源码、构建脚本及虚构页面可入 Git，APK、真实账户、模型副本、截图、凭据及生产日志不可入 Git。实际执行的范围以对应提交的验证记录为准。

实现依据：[Tesseract.js 本地部署](https://github.com/naptha/tesseract.js/blob/master/docs/local-installation.md)、[Appium 固定键盘命令](https://appium.io/docs/en/latest/reference/api/appium/)。
