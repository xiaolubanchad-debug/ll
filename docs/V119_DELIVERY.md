# 1.19 APK 下载结果与补包验收

本次将 APK 资源改为所有下载入口的结果列表，显示原下载结果、失败原因、包信息、来源日期和日志。修复四处嵌套 APK 输出结构漏接 minSdkVersion 导致的查询失败，并区分查询错误与无记录。

失败/停止入口可以由管理员上传有效 APK。文件经中台和节点双重校验，以现有 NodeSlot、Worker 租约及固定签名工具下发到原 node/day/targetKey 缓存。原下载结果及运行快照不改写，管理员后续明确启动的批次才组合使用已下载和补入的包。补包不更新 SDK，不重启 Agent，不启动 APP。

本地验证：264 项契约检查、lint、全模块类型检查与构建通过。原有测试在完整回归中运行至新增补包模块，原有部分通过；新增浏览器测试数据缺少 ID 的问题修正后，补包模块和后续所有测试模块分段复测通过。新增模块使用真实 PostgreSQL、SQLite、管理员二进制上传、受限 Worker 及 Chromium 验证；安装器/SSH 为模拟边界，正式 EC2 缓存验证单独记录。Java 旧网络客户端测试因本机无 JDK 跳过，本次 Java 客户端未改动。Linux 现有工具容器的固定 Playbook 语法检查通过。

新增检查包含成功/无包失败列表、SDK 元数据、权限及 CSRF、格式拒绝、大小限制、损坏及中断、重复会话和并发创建、服务器忙等待、取消/重新下发、签名构件验证、缓存实际回执、后续计划引用、全部下载失败后的补包恢复、旧失败保留、失联隔离、过期来源、发布期间保护以及错误页显示。

操作说明见 [APK 资源与手动补包](APK_ASSETS_RUNBOOK.md)。发布与正式缓存导入的实测结果将在部署后追加；当前不得将本地验证视为正式节点验收。
