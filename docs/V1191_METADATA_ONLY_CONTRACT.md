# 1.19.1 接收文件与 Android 安装判定

按最新要求，APK 上传、下载、缓存及安装前不再执行 ZIP 全量遍历校验、CRC 校验、无关路径拒绝、清单整体大小拒绝，也不执行 APK 签名预校验。Android 安装结果作为能否安装的依据。1.19 的“ZIP/CRC/Manifest 全部校验”由本契约覆盖；历史错误和执行结果不改写。

包名、版本、最低 API、原生 ABI 仍作为运行信息读取，用于启动 APP、选择系统档案及同设备包去重。新读取器仅查找 AndroidManifest.xml 和 lib ABI 名称，不解压 APK 文件树，不使用条目名称创建路径，不检查无关条目或 CRC，不根据清单声明膨胀拒收。临时清单使用系统创建的私有目录和固定名称，流式落盘、随机读取必需字段并删除；最多读取 256 MiB 的清单，中央目录最多 32 MiB，属于有限资源预算。无法取得运行必需的包名等信息单列 APK_METADATA_UNREADABLE，不再显示为 APK 完整性失败。

文件大小上限、路径边界、管理员身份与 CSRF、节点指纹、发布签名、数据库锁/幂等/租约、上传及传输 SHA256 比对继续生效。SHA256 仅确认中台与节点使用同一份文件，不表示 APK 合法或可安装。缓存使用已保存元数据及文件摘要，不重复执行 APK 内容预校验；安装器报告其实际安装结果，未知结果仍不得误报。

ApkMetadata 增加可选 validationPolicy=ANDROID_INSTALL，标识这一处理方式；缺省表示旧记录，不能回写历史。JSON 契约的所有嵌套元数据结构必须一致。Agent 0.15.1 与签名 APK_METADATA_ONLY_V1 能力声明配套发布。新元数据不得交给旧 Agent：执行计划和补包下发须检查节点已支持这一能力；补包可先接收，等待节点更新后下发。SDK/镜像/型号池不改变，部署可使用既有可信基线增量更新。

测试使用自有结构样本覆盖膨胀清单、无关反斜杠/绝对路径、被改 CRC 的无关文件仍可读取必要信息、临时目录清理、包信息读取失败、文件传输损坏仍拒绝、旧节点能力保护和节点回执。真实部署验证只使用自有 APK，不安装/运行第三方目标。任何文件接收成功均不代表 Android 安装成功。
