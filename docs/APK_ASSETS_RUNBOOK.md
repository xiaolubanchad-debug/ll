# APK 资源与手动补包操作

1.20 起按文件名选择和复用 APK。下载和补包只接收文件，不解析清单；安装后由 Android 提供控制包名。同设备不重复抽取同名文件，不同文件可先后安装相同包名。普通 APP 测试点击停止后，清理回执及新空闲心跳齐全时自动释放占用，原异常记录保留。

1. 在“APK 资源”选择北京时间日期，可查看全部、下载成功、失败/已停止或有手动补包的记录。原下载失败原因和下载日志始终保留；查询报错不会再显示成“没有下载”。
2. 当天、本服务器、本配置最新一次下载结束后，失败行可点“上传 APK 补包”，选择本地 APK。接收符合大小限制的文件，保留文件名；能否安装由 Android 判定；不会根据原文件名创建路径。
3. 上传后显示“正在接收文件 → 等待下发 → 正在下发到服务器 → 补包已就绪”。如提示服务器忙，先在服务器页停止任务，等待清理确认。补包不重启 Agent、不更新 SDK、不启动模拟器或 APP。
4. “补包已就绪”后，手动开始原任务（目标已完成时选择新增一轮），新批次将复用原下载成功的包及已确认的补包。正在运行的批次不变；原下载结果不会被改写为成功。普通开始仍复用当天缓存，需重新访问网页时使用“重新下载”。
5. 上传失败可重新上传；已接收文件下发失败可点“重新下发”。等待期间可取消。下发失联或结果待核验时，先检查服务器并完成隔离核验，再明确重试。
6. 历史日期仅供查看，不允许补包进入新一天。中台私有上传文件与节点日缓存分别管理；中台超过七天且无活动引用的文件会安全回收，历史记录保留。

部署需要 API 可写、Worker 只读的同一私有 APK_UPLOAD_DIR，管理员二进制上传入口单独允许最高 512 MiB，其余 JSON 接口保持 256 KiB。正式主机发布脚本会配置持久卷和专用 Nginx 入口，并保留配置快照。新签名工具包含 MANUAL_APK_IMPORT_V1/apk-import.js；APK 文件本身不入仓库或公开文件服务。

1.19.1 起不执行 APK ZIP/CRC/签名预校验，也不因无关 ZIP 路径或清单膨胀拒收。历史 APK_INVALID 保留，可重新上传；包名等运行信息无法读取时单列错误。文件摘要仅用于传输一致性确认。执行节点需更新至 Agent 0.15.1。
