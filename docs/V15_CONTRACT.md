# 1.5 每日下载和循环注册契约

版本 1.5.0，2026-10-28，Agent 0.5.0。用户已恢复开发，最新口径覆盖旧需求中“必须证明画像、型号、App UA 变化才能注册”的要求：业务验收只要求通过 HTTP 代理操作手机 APP 并确认注册成功。设备画像由 APP 自行采集，不对接产品后台，不作为阻断条件；观测仍如实标记作用域，不承诺新的真实手机或不同出口。

## 配置、任务与兼容

保留配置 schemaVersion=1.0、节点 protocolVersion=1.0 及旧 LEGACY 批次。新签名发布能力 DAILY_V1 才能领取新目的批次；配置使用新增落地页 mode/autoWaitMs 时也必须升级。POST /runs 可指定 purpose=DOWNLOAD、REGISTER、PROXY_CHECK；缺省仍为 LEGACY，且不能携带新目的专属参数。普通管理权限、CSRF、幂等键、节点数据库独占槽、租约、回执及未知结果隔离不变。

DOWNLOAD 单独下载，不下发代理，即使来源配置为 FULL 也不安装或注册。按节点、配置容器、北京时间日期生成唯一 dailyKey：同日重复开始返回原批次，不因新配置版本或服务重启再点图标。当天开始的日期固定到批次结束；下载重试数为零，注册不再发现网站。手机屏幕、触屏及三种下载方式保持；落地页可指定 AUTO 等待自动下载或 CLICK 触控下载，默认兼容 AUTO_THEN_CLICK，等待窗口后最多按配置触控；已捕获下载绝不再次主动触控。不能承诺任意站点自身不会重复发请求。

REGISTER 引用同节点、同配置容器、当天已结束的 DOWNLOAD 批次。固定已成功校验文件的 targetKey、包名、摘要、大小、日期和顺序为资产快照；配置 URL/XPath 必须一致，注册流程和代理可保存为更新的配置版本。只选择已适配的启用注册流程，缺少流程或文件时给出明确结果，不猜测提交。旧 APK 不作为当天新包。注册只读取并复核文件，不开启浏览器、不重下载。源下载任务及快照为持久资产目录，不依赖文件名推断元数据。

每日换包采用入口模板：发现时持久化图标 PID 为 entryId，优先匹配同配置内 registrationFlows.entryId。模板可设置 packageName="*"、activity="@launcher"，包名从当天校验后的 APK 读取，安装后通过 Android 固定命令解析该包的实际启动页；控件值支持 {packageName} 占位符。通配包名必须绑定明确入口，禁止全站无条件通配；没有稳定 PID 时仍按精确包名适配。模板定位失败时结束批次并报 FLOW_LAYOUT_CHANGED，不能反复消耗剩余配额或猜测提交。文件、版本或包名变化不等于界面变化；全新产品或新界面需要新模板，系统不宣称能通用识别所有 APK。原精确包名配置继续兼容，新入口字段和自动启动要求 DAILY_V1。

PROXY_CHECK 只做认证 HTTP 代理与 HTTPS 出口探测，结果属于 PROBE_ONLY，不安装或打开产品 APK。可显式选择已保存代理引用，便于配置尚未切换 FULL 时单独检查。代理口令不进入配置、事件或进程参数。

## 配额与模拟器生命周期

REGISTER 必填成功目标 N、尝试上限 M，均为 1–1000 整数且 M >= N，所有 APK 合计，不按单包分别计算。按照成功下载、已适配 APK 的顺序轮流分配潜在任务。潜在 QUEUED 任务不计尝试；实际进入每轮准备（DOWNLOADING 表示缓存读取）时原子记一次，代理或安装失败也消耗该次。中台校验开始顺序、上一轮已结束、未达到 N/M，以及资产和文件元数据匹配；重复事件不重复计数。

每轮：重新建立代理并探测 → 创建独立 AVD 数据目录和手机模拟器 → 校验 APK 兼容性并安装 → 打开 → 生成账户、屏幕操作注册 → 明确结果及脱敏证据 → 关闭模拟器/Appium/代理并清理 → 下一轮。用户名为密码学随机选取的姓氏和拼音名字组合，6–10 位小写 ASCII 字母；密码 8–12 位字母数字且同时含两类。不修改已经持久化的账户。产品侧名称占用是明确失败，下一轮生成新账户并消耗新尝试；提交结果未知时不得再次提交。

成功达到 N，批次 SUCCEEDED，未使用潜在任务标记 SKIPPED/QUOTA_NOT_USED；达到 M 而不足 N，按已有成功数 PARTIAL_FAILED 或 FAILED，errorCode=ATTEMPT_LIMIT。不存在适配包为 FAILED/NO_ADAPTED_APKS。缓存缺失/损坏可提前结束并报 CACHE_MISSING，不能自动重下载。成功数仅按带账户、唯一提交、APP_UI 证据的成功任务累计，目标、已尝试、成功、失败和未知分别展示。UNKNOWN 或清理不完整立即 NEEDS_REVIEW，不继续下一轮。进程重启沿用 P3 保守恢复，不自动恢复未确认注册。

## 每日调度与停止

新增 GET/POST /schedules 和 PUT /schedules/{id}。保存固定节点、配置版本、发布、北京时间 HH:mm（默认 00:05）、自动注册开关、N/M、enabled。更新必须带 If-Match 与幂等键，每节点只允许一个计划。新计划默认关闭；管理员显式开启后，API 的持久数据库调度每 15 秒检查，只补当天已到时的任务，不追赶之前日期。多 API 进程或重启使用同一计划/日期幂等键与唯一日记录。

每日先 DOWNLOAD，下载终态存在有效新包后按自动注册开关创建 REGISTER。缺少代理或适配流程，计划明确等待修正，不隐式用其他凭据。日记录保存触发时的配置、发布和配额快照，编辑计划不改变执行中批次。新日到时，如果本计划的昨日注册仍运行，持久化安全停止意图，等当前轮次核验并清理后再下载；手动任务或部署占用节点时等待，不抢占。UNKNOWN 保持隔离，不能以新日期绕过。

关闭计划既禁止新任务，也对其活动批次持久化停止意图；排队任务可取消，已领取任务等待节点回执。API 重启后仍落实关闭意图。手动停止、跨日停止不记注册成功，保留已完成项。达到 N/M 后当天不会自动重建注册批次。

## 文件回收与验证

只有新日 DOWNLOAD 全部成功校验后，才在持有本节点独占执行权且没有其他活动引用时清理昨日及更早 APK；部分失败保留旧包但不作为当天候选。目录仅属于本系统，符号链接与路径边界校验不变，失败清理不能伪报完成。数据及设备观测不进 Git。

验收正例：两次同日开始只下载一次；多 APK 共用成功目标；重复结果回执不加次数；前一模拟器清理后下一实例启动；拼音名及密码满足规则；代理检查不启动产品；跨日停止后更新；关闭计划在重启后仍有效。反例：旧 Agent 运行新目的、无代理注册、用旧日文件、篡改资产、越过 N/M、未结束上一轮就开始下一轮、UNKNOWN 后继续、代理失效后直连，都必须拒绝。测试覆盖 PostgreSQL、SQLite、真实手机模式 Chromium、Appium 故障注入及有条件的 EC2 实测；产品注册适配缺失时不得声称已经跑通。
