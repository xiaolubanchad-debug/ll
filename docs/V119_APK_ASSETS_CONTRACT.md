# 1.19 APK 结果列表与手动补包

版本 1.19.0。普通开始继续按当天缓存复用，重新下载仍由管理员手动操作。APK 资源按北京时间下载日期列出所有已发现入口，展示原下载成功、失败、跳过、停止及等待状态、原因、包信息和关联日志。查询错误与空列表分别显示。APK 元数据与 ApkMetadata 共用结构，包含可选 minSdkVersion；额外秘密字段仍拒绝。

管理员可在当天、本节点、本配置最新下载中失败或停止的入口上传 APK。创建上传会话及提交使用管理员会话、Origin、CSRF、幂等和数据库锁；只有文件 PUT 接受二进制，不放宽其他 JSON 路由。流式接收，按配置 maxApkBytes（最高 512 MiB）限流量，ZIP/CRC/Manifest/包名/ABI/SHA 全部校验。文件位于中台私有持久卷，文件名由 SHA 生成，不用原文件名形成路径，不公开下载链接，不执行上传内容。

上传和下发分别为持久状态：UPLOADING、RECEIVING、QUEUED、IMPORTING、APPLIED、FAILED、CANCELLED、EXPIRED、NEEDS_REVIEW。原下载 Task/Run 状态、原因、日志及计数不变，补包独立保存。流传输中断可重传文件，不重复创建下发；未知的节点写入不伪装成功。

节点空闲且任务开关关闭后，以 APK_IMPORT 操作下发。使用现有数据库 NodeSlot、全局库锁、幂等、Worker fence/lease、主机指纹及远程安装锁；服务器忙时等待，不修改运行快照，不打断当前 APP。签名发布声明 MANUAL_APK_IMPORT_V1 并包含 apk-import.js。固定 Playbook 验证构件 SHA，将输入 JSON 当文件复制，以 apk-runner 运行已签名校验工具；工具再次校验 APK 并写入现有 node/day/targetKey 缓存。APK_IMPORT 不重启 Agent、不安装 SDK、不启动模拟器或 APP，不改变节点发布身份。完成必须有匹配导入 ID、完整元数据和缓存 key 的节点回执。停止/失联沿用隔离及核验规则。

APPLIED 才进入同一来源下载的后续可用资产集合。仍只给管理员手动开始后的新批次使用；上传不自动开启测试。最新下载已有成功包的入口不能被补包覆盖；来源已被新下载取代或跨日则不下发。原下载全部失败时，存在已确认补包也允许后续执行；原始失败记录仍保留。缺失的补包缓存由既有安装前校验报告，不偷偷访问原网站。

跨日补包不进入新日任务；过期上传停止派发，历史元数据保留。私有文件安全回收只针对超过七天、无活动接收/下发/核验及无其他记录引用的 SHA；不删除任务、历史证据、节点当前文件或账户。

验收包含含 SDK 元数据的列表、无包失败行、日期/服务器/状态分页、错误页、成功行和失效来源拒绝上传、未认证/错误 CSRF/格式/超限/中断、幂等和并发、主机身份/签名、节点忙等待、实际缓存确认、停止/失联、补包与自动成功包组合、历史不变和跨日。真实联测仅用自有 APK；部署和缓存导入分别标记，原始文件与执行证据不入 Git。
