# 1.13 APP 启动停留并发与每日额度

版本 1.13.0，Agent 0.11.0，2026-10-30。仅 APP_OPEN 增加 1/2 路并发，缺省 1。配置为 `execution.appOpen={dwellMs:10000,concurrency:1|2}`；出现 concurrency 字段即要求签名功能 `APP_OPEN_PARALLEL_V1`。旧不可变版本、旧注册结果及未知提交不迁移、不重放。

整台服务器仍只有一个活动批次；并发发生在该批次内部。下载、独立代理检查和部署与 APK 执行互斥。旧表单注册保持串行。每轮有独立 AVD、代理桥、控制台/设备端口对、工作目录与资源记录；ADB 服务器共享回环监听，所有设备命令固定使用独立 serial，不停止共享 ADB。端口探测与进程启动之间保留进程内占用，清理失败不释放该端口。

调度器同时预留执行中的完成名额，`已完成+执行中 <= N`，`累计已开始 <= M`。失败可在 M 内补充轮次；用户要求的七猫验证使用 N=M=20，合计最多 20 次，最多同时 2 次。任务顺序由 position 确定，可乱序完成；事件仍由同一持久 Outbox 顺序投递。领取、租约、fence、数据库行锁和幂等规则不变。RUN_FINISHED 必须在所有执行中的轮次完成清理后发送。

共享缓存仅打开一次，直到所有执行中的轮次结束才释放 pin 和关闭缓存；当天只下载一次，不因并发重复下载。同一路的前一模拟器完整关闭后才复用该路，另外一路可以继续运行。SQLite 新增按 delivery/task 保存的 android_slots 资源表，清理一项不能覆盖另一项。重启枚举所有槽及旧单资源记录，只清理并回报，不能恢复 APP 执行。任何槽清理失败都停止新增轮次、取消其余正在执行的轮次，等待全部清理后隔离整台节点。停止回执不能在其余槽仍有资源时声称清理成功。

新模式每天北京时间总尝试上限暂定 800；所有任务、手动新增轮次和已归档历史共同累计，停止/修改配置不清零，失败或取消的已开始轮次消耗额度，未开始不消耗。完成目标 N≤尝试上限 M≤800。创建缓存执行批次时在节点锁内核对当日余额，M 超过余额拒绝，事件开始时再次核对。计数来自不可删除的执行历史，不建立可由浏览器覆盖的计数器。旧 0.10 APP_OPEN 历史的 REGISTER 批次纳入日累计，旧表单注册不纳入本额度。新建 APP_OPEN 禁止使用 LEGACY 单次混合下载执行入口，避免绕过每日账本。

新 DailyExecutionPlan 可带 `openPolicy={concurrency:1|2,dailyLimit:800,admissionDeadline:<当天23:55北京时间的UTC时间>}`。新 Agent 的 APP_OPEN 必须使用该策略。23:55 后停止新建轮次，已开始轮次等待完成；不足目标以 DAY_CUTOFF 结束，按已完成轮数展示，不补到次日。中台同时核对截止条件。00:00 沿用跨日停止与清理；00:05 新下载等旧批次全部释放节点后才执行。未清理不得并行下载或部署。

TaskPlanView 新增可选 concurrency 和 dailyUsage（day、limit=800、used、remaining）；TaskCycleView 新增可选 concurrency，来源为历史快照。RunSummaryView 新增可选 concurrency、activeTasks（最多2项），保留 activeTask 兼容字段。页面显示两路当前状态、合计完成数、合计尝试数和服务器当日剩余额度；旧统计不改含义。

正例：N=3、M=5、并发2时先开两轮，完成一轮后仅再预留一轮；全部清理后完成3，不会多开第4轮。失败消耗M，额度不足拒绝新批次。反例：第三个并发轮次、N/M/日额度越界、跨截止时间新增、旧节点接收新配置、一个槽关闭清除其他槽资源、清理失败后仍补轮次均拒绝。

验证分别记录：契约/单元/真实数据库及浏览器、自有 Android 并发、签名发布和部署、七猫2路合计20次实测。耗时以同一批次完整回执为准，并记录安装/启动/停留/清理的真实重叠、成功失败数与峰值活动数；未实测不宣称吞吐翻倍。

发布前验证：204 项契约检查、lint、TypeScript 检查、全量数据库/SQLite/Chromium 回归及构建通过；最后补充的混合资源恢复保护已通过执行端构建和 5 项并发/重启测试。EC2 自有 iota APK 两轮同时执行，实际模拟器峰值 2，两个启动停留结果与清理均通过，未提交表单账户、未上传原始画面。该记录属于候选源码与自有 APK 验证；签名发布、生产部署及七猫20次测试以独立运维回执记录。
