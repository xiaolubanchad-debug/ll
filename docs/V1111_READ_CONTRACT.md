# 1.11.1 页面切换读取与启动加载

2026-10-30，Agent 0.9.1，HTTP 契约 1.11.1。配置结构不变，节点事件增加只读 WAIT_OVERLAY、受限启动恢复 RETRY_LOAD 和公告关闭方法 BACK；中台先升级以接收新事件。签名发布、固定版本快照、节点独占、停止回执、内容隔离及唯一提交规则不变。本次只复用已有下载资产，不触发下载或隐式下载修复。

## 有界只读恢复

Appium 的 source/screenshot 只读请求在连接中断、超时或服务端暂态错误后，仍最多重试一次；第二次读取前增加 400 毫秒退避。退避和下一次请求使用同一有效停止/阶段信号，包括构造函数信号；停止或期限到达时立即结束，不发送第二次请求。会话丢失、权限拒绝、非法响应和证据校验错误不重试。点击、输入、返回、安装、启动和注册提交不采用此重试规则。错误正文仅在内存内判断，不进入日志、证据或异常消息。

正例：页面切换中第一次 source 返回 500，在同一期限内退避后第二次读取成功；退避期间停止则只请求一次。反例：连续 500 时第三次请求；重试 submit；重建会话或重新打开 APP 来重复已提交注册；输出服务端错误正文。

原生 UI 文本、描述、提示和资源 ID 只解码一层 XML 的五个预定义实体与合法 Unicode 数字字符引用，使换行、引号及 & 等定位值与 Android 实际控件一致。继续禁止 DOCTYPE/ENTITY，不启用通用实体展开或递归解码；非法字符、代理码点和越界码点拒绝。`&amp;#...;` 解码后仍为字面 `&#...;`，不能二次解释成注册指令。解码后的正文与定位器仍仅留在执行节点内存。

## 加载状态与入口识别

只有本 APP 界面明确显示受限加载词、没有输入框、没有注册/登录/账号/同意语义、没有可操作控件时，才视为启动加载。不得把网络失败、空白页、内容页、弹窗或缺少注册入口直接等同于加载。

明确加载期间不抓取图片或执行 OCR，不递增普通无入口的短等待次数；每隔 400 毫秒读取新快照，仍受既有发现总期限、观察次数上限、停止和租约限制。退出加载后重新处理广告和弹窗，再核对注册入口和表单。持续加载结束为 AUTO_LOADING_TIMEOUT，不生成账户或提交，不算注册拒绝。其他页面沿用既有否定与待适配规则。

正例：加载页持续超过三次普通短等待，之后广告可关闭、注册入口出现；加载期间截图服务尚不可用，但不影响原生加载观察。反例：把“网络失败请重试”当作持续加载；跳过加载页上的可操作公告或同意控件；等待无限延长；未发现表单而猜测按钮提交。

关闭广告后若出现有明确遮罩语义、但尚未出现可验证关闭控件的过渡层，先保持只读观察，每 400 毫秒读取，最多等待 15 秒，并受剩余总时限约束。过渡期间不点击中心图像、遮罩或未知按钮；出现可靠候选后沿用两次核对，持续无法核验则 AUTO_OBSTRUCTION_UNVERIFIED。新增 APP_OBSTRUCTION action=WAIT_OVERLAY，只可 DETECTED/WAITING；不计为关闭动作，中台显示“等待弹窗加载和稳定”，不需要或产生 ACTION_SENT。

连续弹窗可能使用相同位置、尺寸和关闭图形。对能唯一定位原生关闭控件和其所属面板的 ICON 候选，点击前固定两者的当前 WebDriver 引用；点击后通过同一会话只读检查这两个旧引用。只有旧关闭控件和旧面板均被服务明确判定失效，且两次观察相隔至少 300 毫秒，才确认原层关闭并允许处理下一层。disabled=false/true 不代表引用失效；连接错误、会话错误或服务端错误不能视为失效。控件单独重建、背景动画、图片改变、几何相同的新快照均不足以证明原层关闭。没有可靠双引用时继续使用原来的消失确认；不重发未确认的关闭点击，不重建会话。

原生公告提供全屏“关闭”遮罩语义、能唯一定位公告节点、没有输入框/勾选项/注册登录账号同意入口且不涉及隐私政策或服务协议时，可执行一次固定 Android 返回来关闭公告，method=BACK、action=CLOSE_POPUP，必须带 phase。定位使用唯一资源 ID、唯一短描述（最多 128 字符）或包名、类型和实际边界的精确引用，避免依赖长公告全文查找；点击前两次核对相同公告与遮罩，关闭后仍以两个旧引用均失效的连续观察确认；无效即停止，不重复返回，不点击遮罩中心或猜测外侧坐标。普通内容页、没有明确公告与关闭语义的广告、隐私/服务协议、注册表单不适用此路径。

原生只读面板/公告引用可采用源节点边界内的非空可见裁剪边界，处理长公告滚动容器与 simpleBoundsCalculation 的差异。该包含校验只用于原生对象身份跟踪；实际点击目标和图形触控区域仍须严格复核，不能将裁剪容差用于猜测触控位置。越界、空边界、重复节点或无法定位均不获得执行权限。

## 发布与实测范围

原生功能入口/已绑定表单存在且没有明确遮挡时，优先原生控件，不因可见背景内容持续刷新而反复做全屏 OCR。两次新快照必须具有相同的功能入口角色、唯一定位、位置、字段与勾选结构；新遮罩、外部窗口、目标移动或字段变化均重新读取，不能借背景容差跳过功能核对。位于目标之后且覆盖它的独立大块可操作层会阻止该优化。只有图片入口仍保持原始的页面与像素复核。学习路径记录当前功能摘要，旧路径重新核对后失配即失效。

入口及注册按钮的文字子节点只能归属于唯一、有限尺寸且不含输入/勾选控件的最近可点击父节点；不提升到整屏、WebView 或滚动容器。原生 View 类型的明确注册按钮可与唯一用户名/密码字段绑定，不要求它必须叫 Button；不能绑定时不得点击疑似提交。已经操作过且位置未变的账号/登录入口不因背景或页面标题变化再次点击，应继续选择新的明确入口，仍有歧义则停止。

自动模式的结果仍须提交意图、账户引用和明确的新结果标识，连续复核结果一致；非功能内容动画不再要求整份原始树字节完全相等。空首页、游客身份、目标变化、外部窗口、冲突结果或读取失败仍不能成功。手工流程保持原有配置结果检查。不能可靠绑定的有输入框页面不得把疑似注册按钮作为无账户导航点击。

启动阶段出现明确网络/资源加载失败与唯一“重试/重新加载”控件时，最多执行一次 RETRY_LOAD（method=CONTROLS，必须带 phase）。要求没有输入框、勾选项或注册/登录/账号/同意入口，且执行器仍处于账户生成前的启动观察；不重新安装、不重建模拟器、不切换代理、不访问新下载地址。中台仅在 LAUNCHING/DISCOVERING 且不存在账户记录时接收该动作，并拒绝同一任务的第二次执行。加载重试仍须新快照核对和结果确认；失败或再次出现错误即结束为 AUTO_STARTUP_NETWORK_FAILED，不生成账户。此动作不重发注册，也不适用于已生成、已提交或结果未知的账户。

Agent 0.9.1 保留 APP_READINESS_V1；显式启动设置接受 0.9.0/0.9.1，旧固定发布行为不改写。中台先升级，再部署签名 Agent，节点就绪后建立新的注册轮次并复用同一天的已校验 APK。真实 APP 必须观察明确成功结果；自动分配身份单独统计，不计入成功目标。提交未知停止核验，不自动再注册。

契约正反例、加载分类、阶段期限、退避停止、重复提交保护以及自有 Android 和真实产品注册分别验收。未执行的范围不能以本地测试或自有样例代替。
