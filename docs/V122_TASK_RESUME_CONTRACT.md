# 1.22 任务恢复与等待原因

中台 1.22.0。Agent 协议、SDK、镜像和型号池不变；包含尚未发布的 1.21 功能时仍使用 Agent 0.17.0。沿用 TaskControlInput、TaskCycleView.errorCode 和 RunSummary.stopConfirmed 的运行时 Schema，不新增接口字段或数据库迁移。

## 开始与版本快照

显式 START 恢复未完成的当天任务时，在资料库锁、节点锁和幂等事务内检查节点空闲、在线、已部署、当前发布存在，以及历史未核验结果。新 generation 使用节点当前已安装的 releaseId；同时保留既有预算、已用次数、下载来源和所有旧 Run 的不可变版本。不能修改旧 Run、交付凭据或已提交结果，不能重放未知提交。

当前轮次处于 QUEUED/WAITING 等非终态、但 releaseId 已过期时，START 同样进入上述恢复分支，不能直接把旧轮次开关设为启用。若仍有运行、部署或核验占用，拒绝恢复。没有版本变化的活动任务重复 START 仍保持幂等，不新建批次。

调度创建批次时，节点已经安装且版本与任务快照不同，返回 NODE_RELEASE_CHANGED。只在节点锁下确认当前轮次 generation 未变化、未停止、没有运行中或未核验批次、没有槽位/部署占用后，将本轮次标记 FAILED 并关闭任务开关，保留全部次数和历史；管理员再次 START 才能使用当前版本继续。真实离线、未部署等暂时条件仍使用既有等待逻辑。并发 STOP/START、新批次或版本更新优先，陈旧调度结果不得覆盖新状态。

正例：旧版本 A 的任务已停止且回执齐全，节点已升级 B；点击开始后，新 generation 引用 B，旧批次仍是 A，已用 1 次继续保留。未完成的 WAITING 轮次引用 A、节点 B 且空闲时，也可显式开始恢复。调度检测到版本变化时显示“执行版本已更新，请点击开始继续”。

反例：直接修改旧批次 releaseId、清零已用次数、用旧幂等键重新提交、忽略未核验结果、在部署或任务占用期间切换、陈旧调度错误覆盖刚开始的新 generation，均禁止。

## 页面含义

服务器行区分“等待条件”“执行版本已更新”“已停止”和真正的“待核验”，展示当前轮次错误的可读原因。没有当前批次的 QUEUED/WAITING 状态，日志按钮显示尚未创建批次及等待原因，不把旧的已处理 NEEDS_REVIEW 日志当作本次执行。历史记录仍可通过执行记录查询。

已确认停止的历史批次不再显示其遗留非终态 Task 为当前执行任务；原始 Task/status/error 和核验回执保留。不能因此把未知结果记成成功或失败，也不能单凭节点在线解除核验。

## 本轮交付范围

按用户最新要求只修改和提交代码，不运行自动测试、验证或第三方 APP 流程，不声称测试通过。生产故障处理仅可停止尚未创建新批次的卡住请求，保留历史、次数和回执，不自动重启任务。发布门禁继续保留；免测试部署例外此前被自动审批拒绝，本次未获得明确例外授权，不绕过发布控制。
