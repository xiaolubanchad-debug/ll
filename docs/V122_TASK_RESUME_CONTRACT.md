## 开始与版本快照

显式 START 恢复未完成的当天任务时，在资料库锁、节点锁和幂等事务内检查节点空闲、在线、已部署、当前发布存在，以及历史未核验结果。新 generation 使用节点当前已安装的 releaseId；同时保留既有预算、已用次数、下载来源和所有旧 Run 的不可变版本。不能修改旧 Run、交付凭据或已提交结果，不能重放未知提交。

当前轮次处于 QUEUED/WAITING 等非终态、但 releaseId 已过期时，START 同样进入上述恢复分支，不能直接把旧轮次开关设为启用。若仍有运行、部署或核验占用，拒绝恢复。没有版本变化的活动任务重复 START 仍保持幂等，不新建批次。

用户进一步明确点击开始后应直接执行，不能因版本变化自动关闭任务开关。调度创建批次时，节点已经安装且版本与任务快照不同，返回 NODE_RELEASE_CHANGED。只在节点锁下确认当前轮次 generation 未变化、未停止、没有运行中或未核验批次、没有槽位/部署占用后，为已开启的任务自动创建新 generation 并采用节点当前 releaseId，清空旧代理检查引用、标为 QUEUED，保留 enabled=true、全部次数和历史；下一次调度使用新快照继续，不要求再次点击开始。真实离线、未部署等暂时条件仍使用既有等待逻辑。并发 STOP/START、新批次或版本更新优先，陈旧调度结果不得覆盖新状态。

正例：旧版本 A 的任务已停止且回执齐全，节点已升级 B；点击开始后，新 generation 引用 B，旧批次仍是 A，已用 1 次继续保留。未完成的 WAITING 轮次引用 A、节点 B 且空闲时，也可显式开始恢复。已开启任务由调度衔接时保持开关开启并显示准备执行，不因版本变化自动停止。

反例：直接修改旧批次 releaseId、清零已用次数、用旧幂等键重新提交、忽略未核验结果、在部署或任务占用期间切换、陈旧调度错误覆盖刚开始的新 generation，均禁止。

## 页面含义

为复用指定缓存进行真实验收，execution.appOpen 增加可选 assetFileNames，保存最多 1000 个安全 APK 文件名的明确选择，省略表示沿用全部可用文件。它只在建立执行快照时过滤资产，不触发下载，不改变原下载记录。同名比较不区分大小写；历史记录采用 1.20 的 history-来源短键.apk 名称。选择的任一文件当天不可用时明确返回 APK_SELECTION_UNAVAILABLE，不能退回随机执行其他文件。每台安装数量仍须不超过所选可用文件数。界面支持逐行填写并保留选择；空输入恢复全部可用文件。用户要求 55 真实十轮验收时，使用已确认的现有文件、每台一个 APP、合计十轮，完整执行代理、新模拟器、安装、打开、停留十秒、卸载和清理，不重新下载。

服务器行区分“等待条件”“版本衔接中”“已停止”和真正的“待核验”，展示当前轮次错误的可读原因。没有当前批次的 QUEUED/WAITING 状态，日志按钮显示尚未创建批次及等待原因，不把旧的已处理 NEEDS_REVIEW 日志当作本次执行。历史记录仍可通过执行记录查询。

已确认停止的历史批次不再显示其遗留非终态 Task 为当前执行任务；原始 Task/status/error 和核验回执保留。不能因此把未知结果记成成功或失败，也不能单凭节点在线解除核验。

## 本轮交付范围

此前按用户要求仅修改和提交，未运行测试；用户现明确要求“测试了再发布”。本次恢复正常契约、代码、类型、构建及回归检查，通过后按原发布门禁增量部署，记录实际通过的范围。生产故障处理仅停止卡住请求，保留历史、次数和回执，不自动重启任务或运行第三方 APP。发布门禁保持原样，不使用免测试例外。
