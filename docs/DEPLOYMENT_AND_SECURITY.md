# 部署与凭据管理契约

版本 1.1.0。中台保存服务器接入资料并通过固定部署流程安装 Agent。P1 具体行为及当前验证范围见 [P1 契约](P1_CONTRACT.md) 和 [部署说明](P1_SETUP.md)。日常测试通过节点 HTTPS 通信，不依赖 SSH 执行每个业务步骤；业务执行属于后续阶段。

## 接入信息

NodeConnection 包含显示名称、host、SSH 端口、用户名、credentialVersionId、预期主机公钥指纹和可选 sudo 凭据版本引用。只接受明确的 IP 或域名，不接受命令、URL、换行或任意 SSH 参数。

支持私钥、私钥口令和密码登录。私钥文件在上传接口接受，不能作为普通节点 JSON 返回。每条凭据保存独立版本、加密密文、keyId、创建者和查看审计。中台页面只显示 hasSecret、凭据类型与版本，不回显私钥或代理密码。

新服务器首先执行只读指纹探测，管理员将探测值与可信 EC2 资料核对并保存 expected fingerprint。探测值本身不是身份认证，不能自动当作可信值。后续部署必须严格比对，指纹变化直接失败，不使用 StrictHostKeyChecking=no。

## 网络和权限

| 连接 | 规则 |
| --- | --- |
| 浏览器到中台 | HTTPS 443，安全会话，所有管理路由鉴权 |
| 部署 Worker 到 EC2 | SSH，EC2 安全组仅允许中台出口地址 |
| Agent 到中台 | 出站 HTTPS 443，校验证书，独立节点身份 |
| Appium 与 ADB | 只在节点本机可访问，不向公网监听 |
| 数据库 | 中台私有网络，不向公网开放 |
| 安卓到代理 | 仅按配置使用 HTTP 代理，不宣称覆盖所有协议 |

中台 SSH 目标可以是管理员录入的私有地址。此权限与测试网站访问分开：网站和落地页默认禁止 loopback、RFC1918、link-local、云 metadata 地址及对应 IPv6，每次重定向和解析后复查；浏览器和下载网络也使用宿主机出口规则，避免仅做字符串判断后被 DNS 重绑定绕过。

Agent 以专用低权限用户运行，只加入需要的 kvm 组，不以 root 运行 APK。部署时的 sudo 权限只用于安装和服务配置。节点不持有 SSH 私钥、数据库口令或整个站点的代理凭据列表。

第一版不接入 AWS Access Key，不创建、重建、终止 EC2，也不自动修改 AWS 安全组。配置测试 URL 和注册步骤不授予任意远程代码执行能力。

## 密钥生命周期

管理员密码使用 Argon2id 摘要；会话使用 Secure、HttpOnly、SameSite Cookie，并对写操作进行 CSRF 检查。Agent 采用独立 Bearer 凭据，不使用管理员 Cookie。bootstrap 令牌仅用于一次注册，过期即失效。

SSH 私钥、密码、代理口令和测试账户采用 AES-256-GCM 或等价的认证加密。主密钥放在宿主机保护文件或专用秘密服务，不进入 Git、镜像或同一数据库备份；密文带 keyId，支持轮换。数据库单独泄露不能直接恢复秘密；应用与主密钥同时泄露不在此保证内。

每个任务只下发其引用的固定代理凭据版本。传输使用 TLS，节点本地使用受限目录和独立本机密钥加密，不把完整任务含秘密写入日志。普通配置接口只返回引用，节点任务下载接口才在有效租约内解密下发。

部署需要的临时私钥写入 0600、独立作业目录，敏感 Ansible 任务使用 no_log，结束或异常后清理。命令行参数不得包含代理密码或私钥内容；不能通过完整异常堆栈绕过脱敏。

Node 令牌、SSH 密钥和代理凭据都提供吊销入口。凭据版本吊销阻止下一次下发；不能通过“更新为最新版本”改变已固定任务。正在运行任务通过停止和 reconcile 协调，而非悄悄替换密码。

## 部署任务状态

QUEUED → CONNECTING → CHECKING → INSTALLING → CONFIGURING → STARTING → VERIFYING → SUCCEEDED。任一步可以 FAILED；停止请求先 CANCEL_REQUESTED，确认结束才 CANCELLED。进程或节点状态不确定则 NEEDS_REVIEW。

部署前检查系统、x86_64、可用空间、SSH/sudo、端口冲突、KVM 和外网依赖访问。完整安卓就绪需要 emulator -accel-check 及一次空模拟器启动检查，不能仅检查 CPU flag 或 /dev/kvm 是否存在。

首次完整安装按固定发布清单安装 Node、Python/Ansible 所需部分、Java、Playwright 浏览器、Android SDK、固定镜像、Appium 和兼容驱动。大依赖下载可缓存，但必须核对摘要。许可证及首次 sudo 需求在部署预检查中明确展示。

重复部署使用幂等 Playbook：不重复创建用户、不无条件清空数据、不覆盖有运行任务的目录。节点占用时拒绝升级并显示 NODE_BUSY。部署失败保留当前已知状态，不能将中间失败误报为成功。

## 构件和升级

发布清单至少包含 releaseId、Git commit SHA、Agent 构件 SHA-256、签名、Node 版本、协议版本、配置 Schema 版本、Playbook 版本、依赖版本和数据库兼容范围。构件传输走 HTTPS，并校验摘要与可信发布签名；只从仓库已发布的固定版本部署。

安装到 /opt/apk-platform/releases/<releaseId>，运行身份和可写数据放 /var/lib/apk-platform。启动验证通过后才将 current 切换到新版本。验证失败可以回退到前一个兼容版本；已发生的产品注册和不可逆系统变更不能随版本回退。

systemd 托管 Agent，配置重启退避；启动后先 reconcile 旧任务再领取新任务。安装完成不代表 Agent 在线，Agent 在线不代表安卓可用，部署成功必须记录节点回执及环境检查报告。

取消安装应尽快停止作业并标记实际完成步骤，不承诺已经安装的软件全部卸载。第一版不提供递归删除整机目录、重装系统或自动卸载整套安卓环境的按钮。

## 备份与恢复

中台定期备份 PostgreSQL、证据索引和加密主密钥，主密钥单独保护并测试恢复。节点本地记录不得在收到中台结果 ACK 前清除。中台恢复后先隔离恢复前未完成任务，与 Agent 核对，再允许执行新任务。

磁盘不足应暂停新任务并回传原因，不删除仍被运行或 UNKNOWN 结果引用的证据。日志和 APK 清理由引用关系及保留期共同决定，不按目录年龄直接递归清空。

## 审计

至少记录管理员登录、节点添加与修改、主机指纹确认、凭据创建和吊销、部署与升级、配置版本发布、开始与停止、核验决议、查看账户秘密和删除。审计包含操作者、对象、时间、请求 ID 和结果，不包含秘密正文。
